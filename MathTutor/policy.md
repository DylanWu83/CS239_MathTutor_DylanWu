P1. The curriculum agent may use learner context supplied by the application to recommend a learning objective and level of challenge, but must not generate questions, diagnose answers, or change learner records. The question generator may create an item only from an accepted curriculum plan; it must not select or change the learning objective, diagnose answers, or change learner records. The diagnostic agent may evaluate a submitted response to the displayed item, explain the result, identify a likely learning need, and recommend a next step, but must not create or replace the item being evaluated or change learner records. No agent may invoke, direct, or delegate work to another agent or perform application or storage actions.

P2. The application must run curriculum planning before question generation, and must generate an item only from an accepted plan. It must present the item before diagnosis, and may start diagnosis only after the learner submits a response to that item. If a required input or accepted output is missing or invalid, the dependent stage must not run; an agent must not skip a prerequisite, substitute for another agent's responsibility, or treat a missing result as successful.

P3. The application must provide each agent only the context needed for its role: relevant learner context to the curriculum agent; the accepted plan to the question generator; and the current item, learner response, and relevant learner context to the diagnostic agent. An agent must use only its task input and must not request or infer access to another learner's information, unrelated application data, or another agent's private context. Outputs may pass between stages only through the application and only when needed by the next stage. Agents must not communicate directly or retain information for use outside the current task. Learner information and generated content must remain within application-approved processing and storage boundaries and must not be sent to an unapproved service.

P4. The application alone may read, persist, change, or delete learner records. Agents may receive a limited learner-context summary but must not access storage directly or write, erase, or replace profile data. The application may apply a diagnosed attempt according to its learner-data rules; it may delete a learner profile only after an explicit user action requesting deletion.

P5. Each agent must return the requested structured output and comply with the application's configured subject, content, and value constraints. Before displaying an output, passing it to another stage, or applying it to learner data, the application must validate it. Invalid, incomplete, or contradictory output must be reported as a failure, must not be treated as accepted, and must not cause a learner-record update.

P6. A generated learning item must match its accepted plan, be solvable without the prompt revealing the answer, and have an answer and explanation consistent with the item. The diagnostic agent must independently check the mathematical answer rather than rely unquestioningly on the supplied key; if its calculation conflicts with the key, it must disclose the discrepancy and evaluate the response using the verified answer. The diagnostic agent may identify a misconception only when the response supports it.

P7. Agent recommendations are advisory and do not authorize bypassing application rules. The curriculum agent may propose the plan for a new item, and the diagnostic agent may recommend a next step after an attempt. The application decides whether to apply a recommendation and must enforce its configured learning progression and learner-data rules regardless of the recommendation.
